# UI/UX Rules

Apply to interfaces and their styling, imagery, and motion, not standalone 3D work, illustration, film, or other visual media. Do not introduce the patterns below by default. They are PolishUp interface design restrictions, not universal usability rules or proof of AI authorship. Review reports policy mismatches without unrequested edits.

These defaults intentionally limit some styling choices. The alternatives illustrate options, not a required replacement style; do not turn them into a uniform sparse, neutral, or enterprise look.

Preserve relevant existing identity, content, behavior, and project conventions during maintenance and extensions. Missing approval records or DESIGN.md do not make an existing product unconstrained. A listed pattern alone does not authorize replacing it during unrelated refinement.

An explicit user request or relevant established project direction can override affected styling defaults. A visual reference the user asks to match or adapt counts as direction for the requested features. A reference found during research, or supplied only for content or behavior, does not authorize copying its styling. Reuse established choices needed for continuity; an incidental effect is not permission to add it elsewhere. Follow applicable direction without repeated approval. The agent's own rationale does not authorize an exception; requesting blue or a modern look does not request a gradient. Otherwise choose an alternative.

| Do not introduce by default | Possible alternatives |
| --- | --- |
| Purple, blue, indigo, or violet gradient themes on heroes, buttons, or backgrounds; gradient-filled headings or metrics; decorative gradients repeated across surfaces | Choose color roles for the product and use solid, contrast-checked text and action fills |
| Blurred orbs, aurora washes, neon glows, colored shadow halos, decorative grid/dot fields, repeating stripes, particles, or beams | Let content, composition, and relevant imagery establish emphasis |
| Frosted-glass panels or floating pill navigation as a style preset; oversized rounding, diffuse shadows, or a thin border combined with a broad shadow on every card | Use task-appropriate navigation, grouping, shape, and elevation |
| Cream/terracotta with dramatic serif type, black/neon themes, newspaper styling, or neobrutalist styling with heavy outlines and hard offset shadows used as a ready-made identity | Choose type, color, and density from the actual subject and brief rather than another preset |
| A repeated announcement pill, oversized centered headline, vague subtitle, paired CTAs, logo strip, and closing gradient banner | Organize the opening and sections around the product's actual message, evidence, and next action |
| Identical icon-heading-description feature cards, tinted bento teasers, nested cards, or a container around every paragraph | Prioritize content and use appropriate rows, sections, comparisons, or object-based cards |
| Decorative uppercase labels above every heading, nonsequential section numbers, arrows on every action, or dots and badges with no actual status | Keep labels and indicators that communicate category, sequence, navigation, or state |
| Repeated colored icon tiles, oversized decorative icon blocks, arbitrary emoji icons, generic sparkles/rocket/shield motifs, or colored side stripes with no meaning | Use a coherent icon family where it aids recognition; keep meaningful warnings and status cues |
| One dramatized word or colored serif italics in every headline, monospace as generic technical styling, or display-sized copy that hides the product and action | Set readable role-based typography; preserve code, identifiers, and purposeful emphasis |
| Decorative terminals, unreadable pseudo-interfaces, generic AI brains/robots, rough placeholder illustrations, abstract 3D filler, or browser frames that obscure the product | Show relevant product information or suitable assets; omit a visual when it adds no information or intended character |
| Autoplaying testimonial carousels, anonymous avatar stacks, decorative KPI rows, or logo walls added as standard social proof | Use relevant, verifiable evidence only when it belongs in the message |
| Fade-and-slide entrances on every section, staggered reveals for every row, repeated bounce, hover-lift, or image zoom used as decoration | Use motion selectively for feedback, orientation, or an explicitly requested expressive treatment |
| Fake blinking carets, typing headlines, pulsing static status dots, count-up statistics, cursor trails, or automatic logo/ticker marquees | Show readable text, actual values, and honest status; keep necessary motion and media controllable |
| Redundant labels, descriptions, helper text, welcome panels, tips, or AI insight panels added to fill a screen | Keep distinct task information; preserve accessible labels, necessary constraints, and recovery guidance |
| Modal dialogs for routine navigation or multi-section work without a need for interruption or protected focus | Use a suitable page or in-place controls; retain a scoped dialog when it supports the task |
| An unchanged starter page with placeholder sections, branding, or asset slots; meaningless dashboard metrics, unwired controls, or shortcut hints with no working action | Build the requested content and behavior; label genuine prototype limits instead of implying working capabilities |

These restrictions concern the decorative uses described, not all blue or purple colors, dark themes, serif fonts, cards, native platform materials, numbered instructions, status indicators, or data gradients. Familiar controls, deliberate avatar fallbacks, loading placeholders, informative diagrams, and a single readable font family remain valid. Do not remove useful behavior or force unusual layouts to look original. No user preference authorizes fabricated evidence or an unsupported accessibility claim.

Replace listed patterns when their removal is part of the requested change; preserve unrelated styling, meaning, and task support. Repair evidenced usability or accessibility problems within scope while retaining unaffected identity. Flag wider concerns without silently expanding the work. Check for replacement presets too. [Impeccable](https://impeccable.style/slop/), [SlopFix](https://slopfix.getbags.app/checklist), and [Paralect](https://www.paralect.com/blog/signs-of-ai-slop-in-design) provide practitioner examples, not prevalence measurements. Do not target detector scores or require a detector.

## Check the result

Check the affected screen as a whole: task priority, grouping, readable type, actual color pairs, useful density, content, controls, states, and responsive behavior. A collection of permitted components can still obscure the task. Match claimed improvements to the delivered artifact; a rationale or screenshot does not prove working interactions or accessibility. Report only checks performed. Use the [UI/UX index](index.md) for unresolved decisions and [Writing rules](../writing/rules.md) for UI copy. Check applicable restrictions and exceptions without turning a narrow repair into a full audit.
