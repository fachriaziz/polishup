# UI/UX Foundations

Use for shared design principles. Topic references can be read independently.

## Judge quality in context

Judge the design by what people can understand and accomplish in context. Account for affected groups, access needs, languages, devices, and input methods. An operations tool and a cultural website can need different density, pacing, and expression.

Polish, novelty, familiarity, and fewer steps can help, but none alone proves usability. Usability concerns outcomes of use in context, as framed by [ISO 9241-11](https://www.iso.org/standard/63500.html); this reference does not reproduce the standard or establish conformance.

## Preserve effective design

Reuse project behavior, content, identity, components, and platform conventions. Make changes within the requested scope; a concrete problem can justify a repair or a proposal for wider work. Distinguish defects, plausible risks, trade-offs, and preferences.

Design for access and informed choice from the start. Follow the [default pattern restrictions](rules.md) for new styling, respecting user requests and relevant existing project direction. Avoid unsupported content; expressive design remains possible within the brief. Minimalism and visual complexity are not quality measures by themselves.

## Use evidence proportionately

Reuse relevant evidence. Investigate unknowns that could change the design, especially costly or hard-to-reverse choices. Revisit affected assumptions without reopening settled decisions.

Use [UX Research](ux-research.md) for unresolved needs and research, and [Design Evaluation](design-evaluation.md) for diagnosis and verification. Screenshots support visible findings; behavior, accessibility, and user outcomes require suitable checks. State material limits and stop when scoped needs are met.

UI/UX guides experience and interaction. [Writing](../writing/index.md) guides meaning and expression; [Code](../code/index.md) guides implementation quality. Add another domain only when its decisions are part of the task.
