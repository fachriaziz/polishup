# Code References

Guidance for creating, refining, and reviewing code. Focus on implementation quality and recurring generated-code problems, not a development workflow or a complete software engineering manual.

Apply [Code rules](rules.md) and other rules relevant to the output.

| Reference | Use when |
| --- | --- |
| [Readability](implementation.md#readability) | Choosing names, organizing control flow, or deciding which comments and documentation help |
| [Simplicity](implementation.md#simplicity) | Choosing reuse, fix location, change scope, confirmation, dependencies, configuration, or generated-file updates |
| [Correctness](implementation.md#correctness) | Checking API and version compatibility, clarifying required behavior, connecting it to product paths, distinguishing result states, handling failures, or checking relevant risks |

These sections belong to one reference, not required stages or separate files. Use the relevant section when needed. Platform-specific and specialized engineering guidance remains outside this domain.
